# exo · expo

A peer of the same Exo server the terminal and desktop examples join, on a
phone. The first screen asks who you are and which server to talk to; the second
is the to-do list.

## There is no domain logic in this directory

Five TypeScript files are hand-written:

```
src/app/_layout.tsx   a stack
src/app/index.tsx     who you are, and the server URL
src/app/todo.tsx      the list
src/peer.ts           a WebSocket and a 50ms pump
src/theme.ts          eight colours
```

Everything else — what a to-do is, what `add` means, how `pos` is computed, what
the wire format is, when a mutation is refused, how the rebase works — lives in
`crates/todo` and reaches here through `crates/ffi` as generated bindings. A
second `apply` in a second language is two definitions of the same thing, and
the first time they disagree the replicas diverge silently. So there is one.

`modules/exo-todo/` is generated and gitignored. Do not edit it; change the Rust
and run:

```sh
just ffi-bindings     # regenerate, then typecheck the app against the result
```

That reads the UniFFI metadata out of a host build of the crate, so it needs no
NDK and no Xcode.

## Running it

```sh
just serve                              # the server, on 8787
nix develop .#android -c just expo-android
```

The app calls into Rust, so **Expo Go cannot load it** — it needs a development
build. `ios/` and `android/` are generated by `expo prebuild` rather than
committed.

Neither mobile toolchain runs on an ARM Linux machine: Google ships the NDK as
x86_64 binaries only, and Apple's linker lives inside Xcode. Build Android on an
x86_64 host, and iOS on a Mac — or let `.github/workflows/expo.yml` do both.

## The server address

A phone cannot reach your workstation's `127.0.0.1`. The first screen defaults
to whatever host Metro is served from, which is usually right, and is editable
because sometimes it is not: an Android emulator reaches the host as `10.0.2.2`,
a simulator as `localhost`, a real device by its address on your network.
